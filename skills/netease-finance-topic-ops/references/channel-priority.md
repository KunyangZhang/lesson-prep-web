# 搜索渠道优先级

| 优先级 | 渠道 | 主要用途 | 可作为最终证据 | 使用规则 |
|---|---|---|---|---|
| P0 | Web Search | 广泛发现线索并通过站点限定定位原文 | 取决于落地页 | 每次运行必须使用；优先搜索S级域名和原始文件 |
| P0 | 公司官网、公告、财报、投资者关系、交易所、监管、政府和法院网站 | 确认事件、数字、原话、文号 | 是，标记为S级 | 所有最终选题必须回溯至至少1条四天内原文 |
| P1 | 权威财经媒体原文 | 补充采访、行业背景、独家事实 | 是，通常为A级 | 至少保存标题、作者或机构、时间、URL和关键句 |
| P2 | `mx-finance-search` | 补充搜索公告、研报、财经新闻、交易所动态、政策 | 视落地原文而定 | 需 `EM_API_KEY`；不得替代Web Search |
| P2 | `tencent-news` | 7x24线索、国内和国际热点 | 线索或B级证据 | 先发现，再回溯原文 |
| P2 | `wechat-article-search` | 搜索公司、行业公众号和深度文章 | 视公众号主体而定 | 必须用具体公司名加事件词，避免泛搜 |
| P2 | `news-aggregator-skill` | 华尔街见闻、36氪、腾讯、微博等聚合补充 | 否 | 用于扩充覆盖面和发现漏项 |
| P3 | `toutiao-news-trends` | 判断大众热度和流量信号 | 否 | 仅计入流量评分，不支撑事实 |
| P3 | `a-stock-analysis` | A股价格、涨跌、成交量和量能验证 | 行情证据 | 仅在上市公司且行情相关时调用 |
| P4 | 搜索引擎、社交平台、热榜 | 发现关键词、舆情与用户问题 | 否 | 不得作为唯一来源 |

## 推荐搜索顺序

1. 用Web Search对目标公司池搜索四天窗口内的公告、财报、监管、门店、价格、产品、渠道、人事、融资、诉讼和召回，并用 `site:` 查询优先覆盖S级站点。
2. 用权威媒体和可用的内嵌Skill扩充线索，不断把每条结果写入逐条资料清单。
3. 丢弃发布时间缺失、窗口外或未来时间的资料，再按规范化URL去重；不足100条时扩大公司池、事件词和站点范围，不得进入选题。
4. 对高潜候选回到四天内的S级原文确认事实，再用A级或B级来源交叉验证。
5. 用热榜与行情工具评估传播性或验证行情。
6. 对最终候选搜索网易财经、网易号外、公众号后台和历史SQLite。

## 搜索完成门槛

- 至少100条四天窗口内的去重资料，不以查询返回总数或搜索引擎估算数量代替。
- 至少有一个渠道明确标记为 `web_search`；Web Search不得由内嵌Skill冒充。
- 每条资料保存结果ID、标题、规范化URL、渠道、等级、发布时间、抓取时间和线索摘要。
- S级资料优先进入候选池；最终4条选题必须分别绑定至少1条四天内的S级原文。

## 降级规则

- 某技能缺少密钥、服务未启动或返回错误：记录 `unavailable` 或 `error`，继续下一渠道。
- 官方页面暂时不可访问：候选标记为 `needs_verification`，不计入成功选题；仍须生成Word并记录未达标原因。
- 聚合内容无法回溯原文：来源等级降为C，不能单独满足证据门槛。
